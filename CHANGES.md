# OPtech2 changes

Changes made on top of Yamagi Quake II Remaster. Upstream history (Yamagi Quake II Remaster) is in `CHANGELOG.old`.

## Unreleased

- Re-release game libraries (game API 2023, as id's quake2-rerelease-dll builds them) load and play: a folder with `game_x64.so` (`game_x64.dll` on Windows) instead of `game.so` gets it; the client game module comes from the same library. The server talks to the library through a bridge (`src/server/sv_game_rr.c`) that keeps engine copies of the game's entities for linking, collision and snapshots, maps configstrings between the re-release layout and ours, converts player state, commands, entity flags and effects, sends localized prints as `svc_locprint`, and lets players and projectiles block only traces that ask for them. Saving and loading work with them (the game's own JSON saves: `WriteGameJson`/`ReadGameJson`, `WriteLevelJson`/`ReadLevelJson` in the usual save folders), and so do level changes: a level you leave is kept and comes back as you left it (monsters you killed stay dead). The game's `CanSave` is asked before saving. New check `rr-saves` (tests/rerelease/rr_save_check.py). Not yet: bots, debug drawing, the weapon wheel and other re-release-only configstrings. Messages the game builds while it plays a sound, prints or sets a configstring are kept intact (those used to be glued onto them), and its match-details data (meant for an online scoreboard) is dropped instead of left in front of its next message; both broke the client with "Illegible server message 0x00". Monster muzzle flash 255 and the 256-item inventory are rewritten for our protocol. `sv_rr_msglog 1` logs every message the game sends; one the client could not read is logged even without it, naming the game function that wrote it. On an illegible server message the client prints the commands before it and the packet's bytes. `rr_edicts [classname]` lists the game's entities with health and position. `tools/rerelease/stock_game` builds id's stock game for Linux out of tree. New checks `rr-game` (tests/rerelease/rr_game_check.py: base1 with the stock game: walk, jump, monsters move, a railgun kills a soldier) and `rr-layout` (tests/rerelease/layout_check.py: the C copy of the API matches id's headers, 299 sizes and offsets).
- Loading a single-player save with `cl_loadpaused` pauses the server before the level runs (it used to pause only once the client had connected, so the level ran a frame or two first and things in the air moved); the `savegame` check runs on the fixed test clock now too.
- A modern console: a dark see-through panel with an accent line (`con_alpha`, default 0.82; `con_style 0` for the classic picture; drawn solid with the plain palette fill when no game runs behind it), text in Hack (shipped in `baseq2/fonts`, its license beside it; `r_ttffont` picks another monospaced font, `""` the bitmap font; a font that isn't found falls back to Hack), a little smaller than the menus (`con_textscale`, default 0.8), and keys repeat while typing in it or in a chat line (not the console key, Escape or Enter). With a TrueType font the console's columns are the font's own width and its lines 13 units apart, so text reads like a terminal (no gaps, underscores and descenders stay on their line). TrueType text everywhere runs at the font's width (menus, HUD and centered texts measure it that way too), single characters go through it, and its texture is smoothed (it was caught by `r_nolerp_list`'s `pics/conchars.*`). Renderers get `DrawFillColor` (a translucent rectangle; the software renderer dithers it) and `DrawCharAdvance`; renderer API version 10.
- Monster navigation adds the re-release navigation files' ladders and teleporters. Ladders (in the player-sized mesh): monsters that size climb them, rising at a steady speed with their run animation (stock monsters have no climb), then step over the top; ladders down are walked off like ledges. Teleporters: a monster whose path goes through one is sent on like a player (the pad and the rogue trigger_teleport); monsters that just wander onto a pad are still ignored. A teleport costs next to nothing however far it goes. The path API gets `OPTECH2_PATH_LADDER` / `TELEPORT` and the link types `LADDER` / `TELEPORT`. The load line counts both; `g_monster_nav 2` logs climbs and teleports. Cache version 10. New check `ladders` (tests/nav/ladder_check.py, map tests/maps/make_ladder_map.py).
- Monster navigation adds the re-release navigation files' long jumps too: one-way leaps across gaps, flagged by length. The re-release keeps them for flyers; here the monsters that jump take them, up to how far each leaps (Berserker, Gunner, Infantry 192 from takeoff to landing, Parasite 256, Mutant 320): at the takeoff they face across and jump with their own animation, at the speed that lands them on the far side. A monster has made a jump once it's near the landing (not only at its height). The load line counts leaps. Cache version 9. New check `leaps` (tests/nav/leap_check.py, map tests/maps/make_leap_map.py).
- Monster navigation reads the re-release's bot navigation files (`bots/navigation/<map>.nav`, format NAV3) and adds their barrier jumps to the mesh: one-way links up onto ledges and over barriers, flagged by height. Monsters with a jump of their own (Berserker, Gunner, Infantry: 40; Mutant, Parasite: 68) take the ones they can make: at the takeoff they face across and jump (their own jump animation, up or down by the path). Jumps onto spots too small for a monster's mesh (crates, narrow ledges), or through gaps narrower than the monster, are left out. A monster back at the same takeoff 1-4 s after jumping gives up and chases the stock way for 5 s. The mesh cache includes the file's checksum (cache version 8). `g_monster_nav 2` logs jumps; the load line counts them. New check `jumps` (tests/nav/jump_check.py, map tests/maps/make_jump_map.py).
- `tools/ci/run_cppcheck.sh` and `tools/ci/run_codeql.sh` run the CI scans locally; the pre-commit hook runs cppcheck on the staged source files and stops the commit on a finding (`OPTECH2_SKIP_CPPCHECK=1` skips it once). `tools/nightly_check.sh` builds, runs every check, cppcheck and reads the GitHub CI and alert state, writing a report to `build/nightly/` (skips while a game runs). README (fixed clock, headless checks, code scanning) and project page updated.
- cppcheck style rules are on and clean: variables declared in the block that uses them, `const` on pointers and arrays that are only read, no names hiding other names (arguments that shadowed globals renamed only inside their own function), prototypes name their arguments like the definitions, floats read from file and draw-list data with `Q_ReadFloat` (memcpy) instead of float pointer casts. The last menu item of a layout no longer bumps an unused `y`. Vulkan texture modes take their sampler from the table instead of its index (same values). File-format structs keep every field (marked for cppcheck).
- cppcheck now checks the whole engine (before, a missing `YQ2ARCH` stopped it in `common.h`, so it only saw the game code). Fixes from that: key events out of range are ignored and the controller-alt menu can't bind past the key table; the hunk allocator catches `mmap` failures (`MAP_FAILED`, not `NULL`); missing out-of-memory checks in lighting, PVS, Half-Life models and the software renderer; signed shifts that overflow (network sequence flags, map surface flags) and negative shifts (sound, console) made safe; unsigned values no longer compared `< 0`; map, model list and download filters use `strtok_r`, the console clock and save names `localtime_r`; dead or doubled conditions merged. Model viewer: skins kept their blue channel (it was zeroed where alpha belonged), a file handle leak, unterminated anim path and unchecked allocations fixed.
- CI cppcheck: force-includes `tools/ci/cppcheck_shims.h` (SDL version macro, a plain out-of-memory check), skips bundled minimp3 and HandmadeMath.
- Hunk overflow error prints its sizes with the right format (they are `size_t`; `%d` could print garbage on 64-bit).
- Code scanning also skips the bundled single-file libraries (stb, pl_mpeg, volk); their warnings are upstream's.
- Image, model, video and screen buffer sizes are multiplied in 64-bit (`size_t`), so a huge or broken file can't overflow the size before it is widened; float math that went through `double` by accident uses the float versions (`ceilf`, `fabsf`). Fixes the 90 CodeQL alerts of this kind in our code.
- cppcheck fixes: the HUD layout stops on a bad stat or loc string index instead of reading out of range; map list and CTF warp use the thread-safe `strtok_r`, the clock uses `localtime_r`; `Q_fabs` is `fabsf` (no float/int pointer cast); dead branches removed (CTF capture bonus, killer yaw, supertank aim, target_changelevel, grenade pause frames, a door speed assignment); lift marking in the nav mesh can't fail, so it isn't a check any more; a few variables renamed or moved into the block that uses them.
- CI cppcheck: knows `YQ2ARCH` and that the aarch64 runner has no SDL3 headers, skips bundled glad and volk, and doesn't report callback parameters that can't be `const` or the re-release API struct (filled by the engine, no constructor).
- `fixedtime <microseconds>` now drives one engine clock: each frame moves it on exactly that much, so scripted `delay` commands and network timers line up with the same game tick on every run, and the game runs as fast as the machine can. Most automated checks use `fixedtime 16667` (one 60 Hz tick a frame); `lift` and `monster-defs` were flaky without it, and checks run several times faster. Checks that time real speed or run a separate server next to the client keep the real clock. Key presses are timed on the same clock (a scripted `+forward` on a fast-running fixed clock lost part of its time).
- `g_monster_freeze 1`: monsters stand still (no moving, turning or attacking) but still take damage. The damage check uses it so the target can't step out of the line of fire.
- Fixes from the lift code review: a lift at the top waits for monsters on it at most 10 s more (an idle monster could keep it from players below forever); a monster waiting at a lift gives up after 8 s and asks for another way (`g_monster_nav 2` logs it); a monster gets all the way onto a lift before sending it (a Tank's box over the edge hit the shaft); the floor on top of a lift is its own mesh area, used only by requests that ride lifts and costing more, so paths don't cut across it, and a monster whose next corner is an open shaft waits at its edge; the game finds the lift by the link's ends with the reach the mesh uses, picks the nearest of several, and skips targeted plats; lifts placed with an `origin` key go into the mesh in the right place; plats left out on some skills aren't in the mesh (cache version 6).
- README: status (M1 done, M2 so far), downloads, re-release episodes, monster navigation commands, and the checks list matches `run_all.py`.
- CI: removed the Microsoft code analysis (PREfast) step from the Windows MSVC build: the action is unmaintained and uses workflow commands GitHub is turning off. CodeQL and cppcheck still scan the code.
- Code scanning, re-release client game code (`src/game/rerelease`): fixed its 137 alerts. Real ones: the ammo and powerup counts in the stats were read and written through a misaligned `uint16_t` pointer (undefined behaviour; now `memcpy`). The rest change nothing at run time: default member initializers on the API structs (`pmove_t`, `sv_entity_t`, `touch_list_t`, `shadow_light_data_t`) and the HUD's own, initialized locals, `const` references, narrower scopes, renamed shadowing variables, C++ casts, dead stores and a dead spectator branch removed in `p_move.cpp`, slerp multiplies in double. cppcheck now runs with `--check-level=exhaustive` (it noted it was cutting its analysis short).
- CI: tag builds no longer attach `.tar.gz` files to the release (the release zips are made by hand while in alpha/beta); `RELEASE_TARBALLS` in `win_mingw.yml` turns it back on. Other tag builds now keep their artifacts.
- Code scanning: results in the bundled libraries (Recast/Detour, Lua, unzip; about 480 of 1054 open alerts) are dropped before upload (`tools/ci/filter_sarif.py` for CodeQL; cppcheck skips them with `-i`). Fixed the alerts in our own code: a possible negative index in the path code, `memset` on Recast structs (now value-initialized), C casts, missing `const`, a script allocator `realloc` pattern, a redundant bound in the client game stats. In the re-release client game code: a missing `return` after `Com_Error` (would read past the muzzle flash table) and a 32-bit multiply widened too late.
- Monster navigation, lifts: `func_plat`s (not targeted ones) go into the mesh where they rest, at the bottom, with a two-way link from on top of the lift to the nearest floor beside its top (cache version 5); `Navigation:` prints how many, and names lifts it couldn't link (7 of about 50 in the stock maps). Requests with `OPTECH2_PATH_ELEVATOR` use them and get `LINK_ELEVATOR` at a lift; `nav_path` uses them too. Walking monsters ride them (`M_NavLift` in `monster/misc/move.c`): onto the lift when it's at their end (else wait, or call it up from the top), send it, stand still while it moves, step off at the other end; `g_monster_nav 2` logs each ride. Stock `func_plat` starts only for players (Rogue's blocked check also lets a monster that bumps into one use it). New test map `tests/maps/make_plat_map.py` (a balcony 320 high, a lift beside it) and check `tests/nav/plat_check.py`: a Berserker rides up to the player in 7 s (stock chase: 12 s) and calls the lift and rides down.
- Fix (lifts): a Tank stood on a lift and never started it: its steps are shorter than its feet are off the mesh, so the path never passed the lift's start. A link's start now counts as passed within 8 units across. And a lift at the top now waits while a live monster stands on it (as it does for players), instead of going back down with a Tank that stopped to shoot (`plat_top_wait`, in the save table). `plat_check.py` rides a Tank up too.
- Monster navigation, ledge drops: the mesh gets one-way links from a floor's edge down to floor up to 256 units below (not into water, lava or slime, nothing in the way), found along every ledge when it's built (cache version 4). Walking monsters take them: at a drop's start the path says `WALK_OFF_LEDGE` and the monster steps off the edge, which stock movement refuses (`M_NavWalkOff`). Requests choose how far they drop (`drop_height`, in steps of 64). `cl_shownav` draws the drops; `g_monster_nav 2` logs each one a monster takes; `g_monster_nav 3` also draws every monster's path as it follows it (single player). New test map `tests/maps/make_ledge_map.py` (a 128 and a 320 ledge) and check `tests/nav/ledge_check.py`: a Berserker on the low ledge walks off it to the player; on the high one it stays up.
- Monster navigation: a mesh for each of three monster sizes (small: the player, soldiers, berserker; medium: tank, gladiator; large: supertank), each kept 8 units further from walls than the size so monsters don't scrape corners. Monsters use the smallest they fit (`GetPathToGoalSized` in the `optech2_server` extension, now version 2); `nav_path ... medium`, `cl_shownav 2` and `3` show the others. Stock maps build in about 0.4 s, once. The test map's wall has a narrow slot too: player-sized monsters take it, bigger ones the wide gap.
- Monster navigation, phase 3: walking monsters that can't walk straight at their goal follow the navigation mesh (`M_NavStep` in `monster/misc/move.c`: asks for a path every 0.25 s or at each corner, falls back to the stock chase when there's none). `g_monster_nav 0` turns it off. On the test map (now a low wall: seen over, not climbed) a Berserker reaches the player around the wall in about 8 s; the stock chase took about 14 s. New check: `tests/nav/monster_nav_check.py`.
- Fix: at 60 Hz monsters missed most sounds and sight alerts: they counted for one server frame, and monsters think every 6th. They now count for one monster think (0.1 s); a Berserker that can't see the player heard a shot 6 times of 6 (before: 0 of 6).
- Monster navigation, phase 2: the engine answers path requests the re-release way (`GetPathToGoal`: start, goal, flags and move distance in; return code, next two move points, path length and corners out), with the request and answer in plain C with the re-release's layout and codes (`src/common/header/optech2_path.h`). The server hands it to the game library through a new `optech2_server` extension (`gi_optech2` in the game library); an older game library just doesn't take it. A request's `draw_time` draws the path in magenta (single player); so does `nav_path`. Cheat command `navtest x y z` asks for a path from the player.
- Navigation mesh (monster navigation, phase 1): when a map loads, the server builds a Recast/Detour navigation mesh from the world's solid brushes (clip brushes included, doors and lifts not) for a player-sized monster, in 512-unit tiles, and caches it in `navigation/<map>.otnav` in the game folder (under 0.2 s for stock maps; then loaded in about 1 ms). Console: `nav_info`, `nav_path x1 y1 z1 x2 y2 z2`, `nav_rebuild`; `cl_shownav 1` draws the mesh in single player. Recast/Detour 1.6.0 is bundled unmodified in `src/common/nav/recast` (zlib license); the engine now links C++. New test map `tests/maps/make_nav_map.py` and check `tests/nav/nav_check.py`.

- Fixed: in single player the server only stepped on client network frames. With vsync on a 144 Hz monitor that was ~48 per second, so a 60 Hz server lost frames: game time ran ~6% slow and monsters stuttered. The local server now steps on its own clock (game time 4.98 s per 5 s real, was 4.68).
- Fixed: gun model jittered while turning at high tick rates. The sway used one server frame of view turn scaled up 6x; how many inputs land in a frame varies (0-3), so it jumped between 0 and 52 degrees. It is now smoothed over 0.1 s (21-28 degrees in the same turn, like stock at 10 Hz).

- Packet splitting: network messages bigger than 1200 bytes (connect gamestate, big full updates) go out as several UDP packets and are put back together on the other side, instead of relying on IP fragmentation that routers often drop. A lost fragment loses that one message, like a lost packet; reliable data is sent again as usual. Only used with clients on our own protocol; never over loopback (single player).
