# OPtech2 changes

Changes made on top of Yamagi Quake II Remaster. Upstream history is in `CHANGELOG`.

## Unreleased

- Smoother lifts: prediction moved the player against a lift one tick behind, a correction of about 3 units every frame while riding (the jitter on elevators, also in stock Quake II). Replayed commands now see moving brush models moved on by their speed, and the player is carried with the one under their feet (`cl_predict_movers`, on by default). On the lift test map the error while standing drops from about 3.4 to under 1 unit, and by about 85% in total. New: `tests/maps/make_lift_map.py`, `tests/pmove/lift_check.py`.
- Player movement is game code: the shared movement code (`src/common/shared/pmove.c`) is compiled into the game library, the game runs its own copy, and the client predicts with the game library's copy (`OPtech2_GetExtension("optech2_pmove")`, falls back to the engine's copy for games without one). A mod that changes movement now keeps prediction working. `pmove_t` carries `airaccelerate` instead of an engine global; the underwater sound filter is decided by the client from the view position. New check: `tests/pmove/pmove_check.py`.
- Videos: the CMake build now plays FFmpeg videos (`.ogv`, `.mpg`, `.avi`), as the Makefile build did (`AVCODEC_SUPPORT`, on when FFmpeg is found). The re-release's videos (Theora 1080p at 60 fps) played for one second and stopped: their empty "repeat frame" packets now repeat the last frame instead of ending the video. Decoding and scaling use all cores, and a video that falls behind skips frames instead of slowing down, so it keeps real time with its sound.
- Fixed: the end of a video repeated old sound (a long note): once the decoded sound runs out the decoder now gives silence.
- Fixed: Quake II 64's intro waited about 7 s after its camera scene. The re-release `target_changelevel` flags 16 (no end-of-unit screen) and 64 (leave at once) are now followed.
- Fixed: with the client game module, a center message left a bar in the top-left corner (the console separator line it echoes, shown as a notify line). The module now handles center messages alone and the notify area is cleared after its echo, as the built-in center print does.
- Fixed: re-release map messages showed as keys (`$map_shoot_barrels_to_make_them_explo_0`). `Q2Game.kpf` (the re-release's localization and UI files) is now loaded from the data dir instead of the working directory, center and console prints with a `$key` are localized, and the client game module's `Localize` fills in the text and its `{}` / `{N}` arguments (shared with `svc_locprint`).
- Fixed: the client game module's HUD was missing at HUD scale 2 and up (1440p, 4K): the engine passed the HUD rectangle in pixels, but re-release modules expect HUD units (pixels / scale) and multiply by the scale themselves. The cgame check now runs at scale 2.
- Fixed: Quake II 64's intro (a camera scene ending in a level change) went to `maps/(null).bsp`: `target_changelevel` ignored being used without an activator, and pressing a key during the camera left the intermission before a next map was set. A key press now only leaves an intermission that has a next map (as in the re-release), a level exit without one stays put, and the intro goes on to q64/outpost.
- Game menu lists the episodes of the game data (from its mapdb.json), like the re-release: with the re-release data (`-datadir ".../Quake 2/rerelease"`) that is Quake II, Call of the Machine, The Reckoning, Ground Zero and Quake II 64. Picking one asks for the skill, then starts it with the data's own start command (intro video and first map), or at its first map if the data has none. Data without episodes keeps the easy / medium / hard menu.
- `func_eye` (Call of the Machine) spawns as a static brush model and `target_poi` (re-release objective marker) is removed, instead of both being reported as unknown.
- The game library has its own client game module: the HUD code of id's Quake II re-release (cg_main, cg_screen, p_move; github.com/id-Software/quake2-rerelease-dll commit 8dc1fc9, GPL 2) is built into it as C++20 (`src/game/rerelease/`, unchanged except three marked lines in q_std.cpp; build settings in `optech2_prelude.h`). The HUD now comes from that module by default; it draws the same as the built-in HUD (stock screenshot check pixel-identical). The game library links the C++ runtime (statically on Windows).
- Client game modules (re-release cgame API 2022): when a map starts, the client loads `GetCGameAPI` from the game library (or from the library named by `cl_cgame`) and hands it the engine's imports (configstrings in re-release numbering, cvars, zone memory, timing, client names, key bindings, pictures, strings). A loaded module draws the HUD, layouts, inventory and center prints; without one the built-in HUD is unchanged. Strings use the console font for now; localization returns the text as is.
- Client game check: `python3 tests/cgame/cgame_check.py` builds a small test module (`tests/cgame/test_cgame.c`), loads it on base1 and checks every value it reads back from the engine.
- `cl_perf 1`: performance overlay (top left, averaged over half a second): frame rate and frame time (average and worst), engine server and game time per tick, client and render submission time per frame, entities / lights / particles drawn, the game's and the whole system's CPU load, the load of every CPU core and of the game's busiest threads (by name), GPU load and video memory, GPU edge / hotspot / memory temperature, core and memory clock, power and fan speed (Linux; GPU values need amdgpu). Note: with `busywait 1` the frame limiter spins, so the game shows about one full core.
- cvar_t has the re-release layout (M2 groundwork for re-release client game modules): `modified` counts changes (engine code still treats non zero as changed), new `integer` field kept equal to the value, YQ2's `default_string` moved after it.
- Forked from Yamagi Quake II Remaster (511b7b0e).
- Project named OPtech2 (Open Tech 2).
- One-command build: `cmake --workflow --preset default` (Vulkan renderer off).
- Screenshots from the GL3 renderer are captured at the end of the next frame, before the buffer swap. Before, they could come out black or stale.
- `teleport x y z pitch yaw roll`: the cheat command can now also set the view direction.
- Screenshot regression check: `python3 tests/screenshots/screenshot_check.py` (add `--update` to save new references).
- Timedemo now also prints frame-time stats (average, median, 95th and 99th percentile, worst) in ms.
- Benchmark: `python3 tests/benchmark/benchmark.py` plays the stock demos and compares with `tests/benchmark/baseline.json` (`--save-baseline` to replace it).
- Map loader accepts only Quake 2 (IBSP 38, extended QBSP/XBSP, BSPX) and Quake 3 (IBSP 46) maps. Quake 1, Hexen 2, Half-Life, Daikatana, SiN, Heretic 2, Kingpin and Doom map support removed.
- Fixed an uninitialized lump count when a map file has an unknown format.
- Pack files: only Quake 2 PAK and PK3/ZIP (pk2, pkz) are loaded. Quake 1/Half-Life WAD, Anachronox DAT, SiN and Daikatana pack formats removed.
- Network protocols 25 (Quake 2 test demos) and 51 (Heretic 2 demo) removed. Stock Quake 2 (26, 31, 32, 34), re-release (2022, 2023) and OPtech2 (2024) remain.
- Renamed to OPtech2 (v0.1.0-dev): executables `optech2` and `optech2ded`, window titles, console banner and crash report. User data now lives in `~/.local/share/OPtech2` (was `YamagiQ2`).
- Raised client limits: render entities 512 to 4096, particles 4096 to 16384, explosions, beams and lasers 64 to 256, sustained effects 32 to 128, sound channels 32 to 128, queued sounds 128 to 512.
- Code style: `.clang-format` (id style: tabs, Allman braces, return type on its own line) and a pre-commit hook in `.githooks/` that formats only the changed lines. Enable once per clone: `git config core.hooksPath .githooks`.
- Dynamic lights raised from 32 to 128 (GL3, GL4, GL1 and software renderers; Vulkan still uses the first 32). The per-surface light mask is now 4 words, sent to the GL3/GL4 shaders as a uvec4.
- `cl_testlights N` spawns N test lights (1 still means all of them).
- Map loader: removed the unused MAX_MAP_* bounds. Submodels are allocated per map (limit is now the model configstrings, MAX_MODELS - 1, with a clear error). A `.ent` override file can be any size (was lump size + 256 KB, larger files overran the map memory). Maps with more than 256 areas now fail with a clear error instead of overflowing the network area bits.
- Mod list: no longer stops at 32 mods.
- Entities per client frame raised from 256 to 1024, and now enforced: before, a frame with more than 256 visible entities could overwrite older frames the server deltas from. Client entity buffer raised from 1024 to 16384 to hold 16 such frames.
- Window title and renderer banner show the OPtech2 version (were still showing the upstream 8.71RR16).
- Multiplayer check: `python3 tests/multiplayer/mp_check.py` runs a dedicated server and two hidden clients on q2dm1 and checks joining, chat both ways, seeing each other and movement (~40 s, no windows).
- `delay <ms> <command>` console command: runs a command later without holding up the command buffer (a long `wait` chain blocks the commands a server sends while connecting).
- Fixed: two clients started in the same second on one machine got the same qport, and the server treated them as one player. The qport now mixes in the process id.
- Images (HUD pics, icons) per map raised from 256 to 2048. This moves the configstrings, so the network protocol is now 2025 (was 2024); older OPtech2 builds and saves will not match.
- Fixed: the server only sent the first 32 player stats; all 64 the game provides now reach the client.
- `sv_tickrate` (server frames per second, default 10, applies from the next map): the server steps at that rate and protocol 2025 tells clients, which time interpolation by it. The game code still assumes 10, so leave it at 10 until the game is converted.
- Game runs at any `sv_tickrate`: physics steps by the real frame time, while thinks, monster and weapon frames and player animation keep their 0.1 s pace (`level.framenum` is now a 10 Hz counter, `level.ticktime` is one server frame). Lava/slime damage stays per 0.1 s. At 60 Hz, monsters still move in 0.1 s steps (client smoothing comes next). `sv_tickrate` is latched: set it before starting a game.
- Multiplayer check takes `--tickrate N`.
- Client smoothing for high tick rates: monsters and other things that move, turn or animate every 0.1 s have each change spread over the time since their previous one (at most 100 ms), so they move every frame at 60 Hz instead of jumping every 6th frame. Movement and animation frames are timed separately. Same result as before at 10 Hz. `cl_smoothmovers 0` turns it off.
- Fixed: doors, lifts and trains lost distance at high tick rates (a door stopped 3 units short of open and closed at 60 Hz). Pushes are still rounded to 1/8 unit, but the rounded-off part now carries into the next push.
- Smoother view at high tick rates: view bob, view and gun offsets, gun sway and damage/pickup flashes now update every server frame (their per-step amounts scaled to the frame time) instead of every 0.1 s. Weapon model animation frames are spread over 0.1 s like monsters (`cl_smoothmovers`). Lava/drowning and falling damage, player model animation, weapon kick and menu updates keep the 0.1 s pace.
- Fixed: in single player the server only stepped on client network frames. With vsync on a 144 Hz monitor that was ~48 per second, so a 60 Hz server lost frames: game time ran ~6% slow and monsters stuttered. The local server now steps on its own clock (game time 4.98 s per 5 s real, was 4.68).
- Fixed: gun model jittered while turning at high tick rates. The sway used one server frame of view turn scaled up 6x; how many inputs land in a frame varies (0-3), so it jumped between 0 and 52 degrees. It is now smoothed over 0.1 s (21-28 degrees in the same turn, like stock at 10 Hz).
- Monsters at high tick rates work like the re-release: they think every server frame and move and turn a share of each 0.1 s step (distances and yaw speed scaled), while animation frames, frame actions (firing, sounds), attack checks and random direction changes keep their 0.1 s pace. Monsters now move every frame on the server, not only through client smoothing.
- Fixed: chaingunners (and other strafing monsters) slid sideways 3x too far and fast at 60 Hz. The sidestep cap is 8 units per 0.1 s, now split across server frames (re-release does the same). Rogue turrets turn at their 0.1 s speed too.
- Weapons at high tick rates (re-release style): the weapon runs every server frame and fires as soon as an idle, ready weapon is told to fire or switch; animation frames and fire rates keep their 0.1 s pace (a weapon that just fired stays busy until its next frame). Press-to-shot delay at 60 Hz: 16-34 ms (was up to 100 ms). Recoil lasts until the next weapon frame.
- Tick rate check also compares fire rates of 8 weapons (ammo used while firing for 3 s).
- `g_damagelog 1`: prints every hit (time, attacker, target, damage, means of death), for tests.
- Damage check: `python3 tests/tickrate/damage_check.py` fires every weapon at a supertank for 3 s at 10 and 60 Hz and compares damage per ammo (~4 min, no windows). Result: identical except rocket/grenade splash within 6%.
- Default tick rate is now 60 Hz (`sv_tickrate 60`). Set `sv_tickrate 10` before starting a game for stock timing. Multiplayer check defaults to 60 too (`--tickrate 10` for stock).
- AI changes from the re-release: monsters turn twice as fast when the enemy is right next to them (no endless circle-strafing); they see in a wider cone (about 107 degrees each side, was 73), except ambush monsters that have not seen an enemy (narrower); after first spotting someone they wait 0.6 s before firing (plus 0.4 s on easy, 0.2 s on medium); monsters pushed off their point_combat walk back to it; with a clear line to their goal they step straight at it instead of zig-zagging along the 8 chase directions; things stuck inside a solid stop building up velocity.
- Fixed: the bandwidth limiter assumed 10 Hz (it summed the last 10 messages as "one second"), so at 60 Hz clients got 6x their `rate`. It now sums one second of messages at any tick rate. Server cap on a client's `rate` raised from 15000 to 100000 bytes/s; client default `rate` raised from 8000 to 50000 (a 60 Hz fight is about 11-26 KB/s).
- `sv_netstats 1`: the server prints each client's traffic once a second (bytes and packets each way, frames held back by the rate limiter).
- Packet splitting: network messages bigger than 1200 bytes (connect gamestate, big full updates) go out as several UDP packets and are put back together on the other side, instead of relying on IP fragmentation that routers often drop. A lost fragment loses that one message, like a lost packet; reliable data is sent again as usual. Only used with clients on our own protocol; never over loopback (single player).
- `sv_netstats` also prints messages split per second and the largest split message; new client command `cl_netstats` prints the connection's totals (incl. messages reassembled and fragments thrown away).
- `net_fragmentloss N` (testing): throw away N percent of outgoing fragments to simulate a bad network.
- Packet splitting check: `python3 tests/multiplayer/split_check.py` fills base1 with 400 shards, forces full updates (~13 KB, 11 fragments) and checks a clean and a 25% fragment-loss run (~1.5 min, no windows).
- Limits test map: `python3 tests/maps/make_limits_map.py` writes and compiles (ericw-tools 2.x: qbsp -qbism, vis, light with decoupled lightmaps) a 12288 unit hall with 320 brush models and 300 sound speakers into `build/maps/optech2_limits.bsp`. `python3 tests/maps/limits_check.py` loads it and checks: extended QBSP load, over 256 models and sounds received and loaded, player placed and walking beyond +-4096, screenshots lit (~30 s; `--renderer gl3` uses a real window and saves the shots to `docs/screenshots/`).
- `cl_configcounts`: prints how many model and sound configstrings the client got and loaded, with the highest index.
- Limits map: a sealed shadow room (one low light, a thin post) and `--luxel N` (0 = no decoupled lightmap). Checked: GL3 draws the decoupled BSPX lightmap; a 4 unit lightmap gives a sharp post shadow, the stock one a soft blob (`docs/screenshots/m1_bspx_lightmap_stock_vs_4units.png`).
- `python3 tools/get_ericw_tools.py`: downloads the tested ericw-tools release (2.0.0-alpha11, Linux/macOS/Windows, sha256 checked) into `build/tools/ericw-tools/`, which the map scripts use by default. README section "Map tools" pins the version.
- Dependabot no longer checks the mission pack submodules (upstream code); it still checks GitHub Actions versions for the Windows build.
- Project web page in `docs/` (GitHub Pages): progress, what M1 changed, limits table, screenshots, downloads.
- Savegames use a tagged format (version "OPT2-1"): every saved field (517 across entities, clients, level and game) is stored with its name, kind and size, then matched by name on load. Saves keep loading after code changes: new fields keep their defaults, removed or resized fields are skipped. Old Yamagi saves ("YQ2-x") still load if they come from a build with the same game structures; otherwise the load stops with a message saying so (it showed a meaningless "bad string length" error). Level saves are ~12% smaller.
- `tools/gen_save_fields.py` generates the field table (`src/game/savegame/tables/savefields.h`) from the game headers; run it after changing a saved struct (the pre-commit hook refuses a stale table). Pointers it does not know stop it, so none are lost silently.
- Save check: `python3 tests/savegame/save_check.py` saves on base1 (health, weapons, spawned soldiers), loads in the same session and in a fresh game, and compares player and all entities exactly (paused around the snapshots); `--save-to DIR` / `--load-from DIR` test saves across builds.
- WAV sounds: 24 bit, 32 bit and 32 bit float samples (and the WAVE_FORMAT_EXTENSIBLE header most tools write) load; they are turned into 16 bit at load. Before, float/extensible files were refused, and 24 bit went to OpenAL as 8 bit mono (noise).
- `soundlist` shows the right length with the SDL sound backend (it printed output samples as milliseconds: 1 s showed as 22 s).
- Sound demo to listen to: `tools/install_test_content.py` also installs 9 clips (8 bit 11 kHz up to 24 bit and float, 96 kHz, stereo ping-pong and pan sweep, a 30 s piece) and `optech2_sound_demo.cfg`, which plays them in order with a label each (`exec optech2_sound_demo.cfg`, ~70 s).
- Sound check: `python3 tests/sound/sound_check.py` writes WAVs (8/16/24/float, 11-96 kHz, mono/stereo, a 3 minute file), loads them through OpenAL and SDL and checks length, channels and volume (~15 s per backend, no sound output).
- True-color texture check: `python3 tests/maps/texture_check.py` builds a room textured only with PNG/TGA images (300x200, 1024x1024, 4096x4096; no .wal files) and checks GL3 (`r_retexturing` 1 and 0) and the software renderer. All load at their own size. The software renderer turns them into the 256 color palette (colors it lacks, like magenta, come out wrong).
- IQM models (Inter-Quake Model v2), the project's standard animated model format: skeleton, blend weights and animations are baked into frames at load (like MD5/MDR), each IQM animation becomes a frame group named after it. An `.iqm` next to a stock model of the same name replaces it. Little-endian systems only. Limits: 2048 vertices and 4096 triangles per model (shared with the other formats).
- `misc_model` spawnflag 1 (ANIMATE): loops `count` frames starting at `frame`, `wait` seconds per frame (default 0.1). Saves keep working (think function in the save tables).
- `python3 tools/install_test_content.py`: builds the test maps and the IQM test model and adds them to your game folder (only `maps/optech2_*` and `models/optech2/`; config and saves untouched), then prints the commands to play them: `optech2_iqm` (IQM showcase, still and looping animated models; `--extra model.iqm` adds your own), `optech2_limits`, `optech2_stress`.
- `gun_model` takes a full model path with extension (any format) besides the old `models/<name>/tris.md2` short form.
- IQM check: `python3 tests/models/iqm_check.py` writes a two-bone test model (`tests/models/make_iqm_test.py`) into a small map, loads it and checks the bent frames (`--renderer gl3` saves `docs/screenshots/m1_iqm_test_model.png`).
- Entity limit raised: `MAX_EDICTS` 2048 -> 8192, `maxentities` default 1024 -> 8192 (both clamped to 8192; a map may use up to that many).
- Faster with thousands of entities: pushers (doors, lifts, rotators) only test entities the area tree has near their move instead of every entity (same order, so blocking is unchanged); the server's area tree splits down to 256 unit cells, 8 levels deep (was always 4 levels). Stress map (3800 entities): server frame 0.85 ms idle / 3 ms in a 300 soldier fight at 60 Hz, ~550-700 fps.
- Fixed: with more than 1024 visible entities the server sent the 1024 with the lowest numbers, so monsters spawned after many map items were invisible. It now sends the nearest 1024.
- `host_speeds` reports in milliseconds with two decimals (was whole ms) and only prints for passes that ran a game or render frame; it repeated stale game times before.
- Stress test map: `python3 tests/maps/make_stress_map.py` (6144 unit room: 3000 items, 500 rotating pillars, 300 soldiers, spawn closet) and `python3 tests/maps/stress_check.py` (GL3 window, ~1 min: frame times idle and in a fight, base1 for comparison; needs >= 60 fps and a server frame under 16.7 ms).
- Network check: `python3 tests/multiplayer/net_check.py` measures KB/s per player at 10, 40 and 60 Hz (idle, fight, 30 soldiers); `--rate-limit N` tests the limiter (~45 s per tick rate, no windows).
- `playerinfo` cheat command: prints game time, health, ammo and position on one line (for tests).
- Tick rate check: `python3 tests/tickrate/tick_check.py` runs base1 at 10 and 60 Hz and compares door speed, machine gun fire rate, rocket speed and berserker run speed (~40 s, no windows).
