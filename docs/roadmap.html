Roadmap

Six milestones, in order. Each builds on the data formats the one before it settles. M0 and M1 are done; M2, the modding milestone, is close to half way through.

Updated 2026-11-24

Done Partly done Not started
  1. M0

    Foundation

    DONE · 7 / 7

    Base chosen (Yamagi Quake II Remaster), one-command build, first unit plays, code survey, screenshot regression check, benchmark baseline, own name.

  2. M1

    Remove limits

    DONE

    Float positions and wide indices in a new protocol, packet splitting, extended QBSP maps and BSPX lightmaps, ericw-tools, thousands of entities with spatial lookups, IQM models, true-color textures, modern sound formats, savegames that survive code changes, 60 Hz simulation.

  3. M2

    Modding and gameplay systems

    IN PROGRESS · 10 / 21

    Move everything a mod might change out of the engine and into game code or data files.

Client game module 5 / 5

  • Client game API (the 2022 re-release cgame API)
  • HUD in the module (id's re-release HUD code)
  • Effects in the module: explosions, beams, muzzle flashes, trails, footsteps, and how every entity is drawn (powerup shells, translucency, rotating items, linked weapons, flares, the view weapon and its powerup shell, shadow lights)
  • Menus as data: pages are text files with Lua scripts for lists; every menu in the re-release's look on its data, with the mouse
  • Match the re-release APIs so re-release mods load unchanged: client and server game APIs, with the re-release's features (compass, wheels, co-op lives, end-of-unit screen, debug drawing, monster paths); bots come later

Shared game code 1 / 2

  • Player movement as game code, used by the server and by prediction (and smooth lifts)
  • Game code defines its own networked entity fields

Data-driven definitions 1 / 2

  • Text files for items, weapons and monsters (defs/<folder>.items and .monsters)
  • Material files

Mod loading 2 / 2

  • A stack of mod folders with an override order (fs_mods)
  • Scripting: sandboxed Lua 5.4, one script per mod folder (first events: level start, player spawn, item pickup)

Gameplay systems 1 / 5

  • Monster navigation (Recast / Detour): a navigation mesh built for every map in three monster sizes, with ledge drops; walking monsters follow it, ride lifts, and use the re-release's jump, leap, ladder and teleporter links
  • Animation system on IQM: blending, layers, events
  • Physics: Jolt for rigid bodies, ragdolls and debris
  • Scalable Unicode text; HUD and menus that scale (TrueType console and menu text done)
  • Achievements defined in data files

In-game editor 0 / 5

  • Dear ImGui tool windows
  • Editor mode: free camera, click to select, move gizmo
  • Undo and redo
  • Entity panel with live respawn
  • Entity override files loaded at map start

Also done (not in the plan)

  • Re-release monster AI: clear-shot checks before firing, active dodging, the re-release's per-monster tweaks, and the Gunner Commander
  • Runs on the classic or the re-release game data, whichever it is pointed at; re-release-only models and sounds are detected and fall back to the classic ones
  • The re-release's episodes in the Game menu: Quake II, The Reckoning, Ground Zero, Call of the Machine, Quake II 64
  • Vulkan renderer built and shipped with every release
  • Menus in the re-release's look on its data, the classic look on the classic data; the mouse works every menu
  • Automated checks: over forty game checks, most of them headless, run on both data sets

M2 is done when

  • A test mod adds a weapon with a new visual effect, with no engine changes (the Test Gun)
  • The same mod changes a HUD element and player movement
  • Two mods load together (stacked folders, each with its own script)
  • The stock game runs entirely through the client module
  • A monster paths around an obstacle to reach the player
  • Text renders in a non-Latin script at 4K
  • An entity moved in the editor keeps its position after a reload
  1. M3

    Multi-threaded renderer

    PLANNED · 0 / 8

    Self-contained scene description, frontend and backend split, everything through the command list, OpenGL on its own thread, a job system, a single-thread switch for debugging.

    Known issue for M3: the Vulkan renderer is slow on big maps (16 fps on Call of the Machine's mgu2m1, where OpenGL is fast). It is bound by the CPU, rebuilding the world's geometry every frame; M3 keeps that geometry on the GPU.

  2. M4

    Lighting and shadows

    PLANNED · 0 / 24

    Materials with normal and specular maps, real-time per-pixel lights, the stock lighting imported and fitted, shadow maps, a light editor, decals, lit particles, post-processing.

  3. M5

    Supporting systems

    PLANNED · 1 / 12

    Sound occlusion and reverb, large outdoor spaces, hot reload, crash reports (done early: a report with a backtrace on every crash), a Blender pipeline, TrenchBroom documentation, more editor panels.
